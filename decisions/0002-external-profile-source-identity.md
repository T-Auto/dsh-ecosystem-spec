# 0002 External Profile source identity
Status: Accepted
Date: 2026-10-03
Context: An ecosystem Profile may be maintained in an external product repository. The entry point must preserve the owner's policy and identify exactly which immutable source document was observed, without treating a package label or a directory digest as Profile maturity evidence.
Decision: External Profile entries use a discriminated owner-policy branch with `maturityPolicy.kind: "not-applicable"` when the owner does not publish the ecosystem maturity ladder. That branch requires `source.repository`, a lowercase 40-hex `source.revision`, a relative POSIX `source.path` without empty, dot, dot-dot, or backslash segments, a `sha256:` digest of the bytes of that one source file, applicable `productVersions`, declared `imports`, and a `suite` id/version. The digest scope is the exact file at the fixed repository revision and path; it is not the whole Profile directory, registry index, repository tree, or a conformance result. Legacy entries may retain the upstream `status` plus optional `statusSource: "upstream"` branch, but may not mix branches. The registry records the verified local TUI admission source file only after its revision and bytes are independently checked; it does not add a new maturity status or vendor pin.
Consequences: `registry/schema/index.schema.json`, `scripts/profile-validation.mjs`, and the structure verifier reject missing source identity, path traversal, invalid policy, and duplicate IDs. Positive and negative fixtures document both branches and boundary failures. This entry is an ecosystem-index governance decision; Profile semantics remain owned by the external repository. A future dsh-std fixed pin is a separate upstream compatibility decision and is not implied by this registry entry.
