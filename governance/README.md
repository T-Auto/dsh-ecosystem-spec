# 治理总纲

> 本文件说明**谁对什么有权威**，以及本仓库在治理里扮演什么角色。
> 细则见 [`rules.md`](rules.md)，历史决策见 [`../decisions/`](../decisions/README.md)。

## 1. 权威归属

| 资产 | 权威方 | 本仓库的角色 |
| --- | --- | --- |
| 公共协议语义（如 `@dsh-std/core`） | 该协议的上游仓库 | 挂载引用 + 索引登记，不重新定义 |
| 环境身份与可迁移性语义（`dsh-distribution`） | 该协议的上游仓库 | 挂载引用 + 索引登记 |
| 子协议语义 | 该子协议的上游仓库 | 挂载引用 + 索引登记 |
| 范例实现 | 该实现的上游仓库 | 挂载引用 + 说明文档 |
| 产品准入 Profile | Profile 的归属方 | 承载文档 + 索引登记 |
| 生态索引、目录规范、本仓库 CI | 本仓库 | 自有并强制 |
| DSH 内核行为 | DeepSeek 官方 | 不干预，通过 adapter 吸收变化 |

**权威跟随资产**：谁拥有协议或实现，谁决定它的语义与版本。本仓库的索引与文档
只登记事实，不授予状态、不认证实现、不替任何一方表态。

## 2. 本仓库可以决定什么

- 收录哪些协议 / 范例 / Profile（收录不等于背书）；
- 目录规范、索引形状、状态词表、校验规则；
- 说明文档的写法与表述红线；
- 挂载 revision 的升级时机（需要给出理由与证据）。

## 3. 本仓库不可以决定什么

- 不修改挂载仓库的协议语义；
- 不把某个产品的准入要求变成所有生态的强制要求；
- 不任命唯一市场、唯一管理器或唯一参考实现；
- 不宣称官方认证、官方采用；
- 不把 capability / permission / 格式校验描述为安全保证。

## 4. 状态与晋级

状态词只有五个：`Draft`、`Experimental`、`Candidate`、`Stable`、`Deprecated`。
`registry/` 中的状态必须**照录上游仓库自己的声明**，本仓库不发明状态。

进入 `Candidate` 前，协议侧应具备确定的协议坐标、definition、fixtures、失败语义
与多实现证据；本仓库只登记结论，不代替协议仓库做晋级判断。

## 5. 冲突与决策

- 争议先在对应上游仓库讨论；跨协议、跨产品的生态问题在本仓库讨论；
- 影响本仓库结构或收录范围的结论，记入 [`../decisions/`](../decisions/README.md)；
- 拿不准时：不做，先问。

## 6. 表述红线

任何文档不得写“官方标准规定”“dsh 官方认证”“所有 dsh 插件都必须遵守”
“某个实现就是标准实现”。这些含义必须改写为 “community draft”、
“产品准入 policy”、“reference implementation / example”、“experimental proposal”。
